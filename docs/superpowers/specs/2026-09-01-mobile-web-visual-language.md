## 1 问题

`apps/mobile-web` 已经把闭环七面跑通，但触感是桌面页塞进手机：点下去没有按下底、主机行要去点小「进入」、hash 整页瞬切、色阶手写 `neutral` / `emerald`，变更入口还会去电脑上抢审查焦点。这不是「还没接上 Ionic」，是视觉和触控语言还没立项——原方案 §11 明确把它们留到另文。

## 2 不换移动端框架

**不引入 Ionic、Framework7、Vant、React Native / Expo。** 理由：

| 选项 | 为什么不做 |
|---|---|
| Ionic / Framework7 | 自带 Material / iOS 皮，会盖掉 Pier 语义令牌；Web Component 阴影树和 Tailwind 打架 |
| 各家 H5 组件库 | 再造一套按钮/列表，和桌面 `packages/ui` 分裂 |
| 现在重写成 RN | 首壳是 Web PWA；原生是薄壳增强（原方案 §11.3）。协议与七面已经在 React 里 |

壳继续是 **React 19 + Tailwind v4 独立 SPA**。原方案写的「按需 `@pier/ui` 子集」仍然成立，但当前 `dependency-cruiser` 还没放行——落地时再开白名单，不要为了换皮去换框架。

发硬的根因是交互层空着：

1. Tailwind 预检通常会把 `-webkit-tap-highlight-color` 清成透明，又没有自绘 `:active`。
2. 多数列表不是整行命中；主机页把「进入 / 移除」做成 28px 级小钮。
3. Hash 切页是整页瞬切：有「返回」却没有反向运动，空间记忆对不上。
4. 工作台把打开中的文档面板和审查面板列成和终端平级；实现里变更还会 `git.openReviewPanel` 同步桌面。
5. 桌面 28px 密度被带进了手机。

要补的是 **触控积木**，不是第三套 UI 框架：按下态、44px 命中、整行进入、层级栈、铃铛收件箱。过渡优先用 View Transitions API，不必上路由库。

## 4 触控语言

画板 `K1` / `P0` 是对照。实现时收成公共控件，禁止每页手写一套 `active:bg-neutral-800`。

| 规则 | 要求 |
|---|---|
| 按下 | 主路径自绘 `bg-interactive-active`（或主按钮 `opacity-80`）。禁止把 hover 当唯一反馈 |
| 命中 | 主按钮与列表行 `min-h-11`（44px）。会话底栏键帽同高 |
| 行 | 整行进入。主机「移除」不得和「进入」并排抢主路径；破坏动作后置（溢出或确认） |
| 过渡 | 见 §5。有返回 = 必须有反向滑出。没有全局底部导航 |
| 系统高亮 | 可以继续关掉 UA tap 高亮，但必须有自绘按下态顶上 |

不要上震动反馈当 v1 必达（Web 壳没有稳定触觉）。不要为了「像 iOS」去引入橡皮筋列表库。

## 5 页面过渡（工效）

**整页瞬切不是手机工效的默认。** 人靠空间记忆走路：进去是更深一层，回来是揭开上一层。桌面网站可以整页替换；手机上瞬切会让人失去「我从哪来」。现在的壳用 hash 直接卸掉整棵页面树（顶栏也一起死），所以切面像在换网站，不像在同一台设备里往里走。

父子页面使用推入；阅读设置与会话切换使用局部面板，不增加导航层级：

| 动作 | 例子 | 运动 | 时长 |
|---|---|---|---|
| 推入栈 | 主机 → 这台电脑 → 会话 → 变更 / 文件；主机 → 配对；工作台铃铛 → 通知 → 该会话 | 新页从右进，底页左移约 25%。只动 `transform` | 220ms，曲线 `cubic-bezier(0.32, 0.72, 0, 1)` |
| 返回 | 顶栏「返回」、系统后退 | 与推入同曲线反向。有返回控件就必须有这步 | 200–220ms |

**不设全局底部导航。** 主机和工作台不是平级频道：先选电脑，再看这台电脑上的面板。通知也不是第三个根面：它是当前机的收件箱，入口是工作台顶栏铃铛；系统推送点开直接落到该会话。

业界对照（远程监督，不是云执行）：Orca 根面是已配对主机列表，进主机后再看会话；Codex Remote 是 Remote → 选主机 → 任务；Claude Code Remote 是会话列表（已在某台电脑上跑）；Cursor iOS 收件箱按会话，不是「主机 / 工作台 / 通知」三键；Moshi 的 Home 是连接（主机），Inbox 是钩子事件，仍先连上某台机器。iOS 人机界面：底栏只给同级目的地；父子用推入。

其它规则：

- **实现时状态栏 / 安全区不参与横滑**，只滑导航栏 + 正文。画板外框是 Artboard，内页不再画 9:41 / Home 条。
- **配对**：相机即页。玻璃上只留角括号；一只 44×44 实心停止键；底下那一行说明。不要标题「配对」、不要取景框里再写「对准二维码」、不要绿激光、不要相册/粘贴链。
- **工作台**：两列终端缩略预览；Pier 绘制的窗口栏放会话状态，预览外下方放会话名与工具品牌标识。窗口栏不是原生截图的一部分。默认不把会话拆成多块状态分组，也不用任务摘要取代终端画面；沿用桌面 tab short，不生成任务标题或进度。工作树变更另列平实列表。缩略内容复用该会话当前屏幕；T1 为文本缩略，不能画成已实现原生截图或 ANSI 渲染。
- **会话**：导航、连续终端阅读区、底部工具条分别占位。T1 仍只有当前屏幕纯文本，不模拟历史、语法色或可识别选项。底部将回应与阅读分开：有资格时显示「需要你处理」回应区，以主按钮打开按键；字号与会话切换是下方的次要阅读工具。按键在回应区原位展开，数字键二级展开，面板占据布局空间，不遮住原文。关闭后焦点回到回应入口。只有 `waiting` + 有效 `pendingInteractionId` + 在线才开放按键；无登记则提示在电脑处理。
- **按键边界**：现有命令只发送 Enter / Esc / y / n / 1–9；数字键二级展开。不能把 1/2/3 做成当前选项、不能给 Enter 附加「批准」含义，也不能假设数字会直接选择或提交。发送中防重复；成功只显示「已发送」，终端变化与回合完成必须等待独立事实。过期反馈阻止继续发送，失败允许重试。断线保留最后内容并明示，停止展示回应入口。
- **变更**：按 git 根给工作台入口，从会话进入时保持该工作树作用域。文件名为主、目录为辅、增删数量固定在右侧；长文件名可换行。竖屏使用单栏合并 diff，原文与导航分开，不套多层内容卡。电脑上不弹审查。
- **文件**：仍只从会话头部进入，工作台不列文档面板。目录与文件使用明确图标，行高至少 44px，路径显示所属工作树；源码预览有行号、可读语法色和长行换行。文件名优先完整显示；进入目录在当前页面更新，不另推页面。
- **无会话空态**：说明「这台电脑现在没有可投影的会话，请在电脑上开一个」。不要「新建智能体 / 新建终端 / 新建工作树」。
- **文件页在目录里往下走不是推入新页**，只更新列表；推入发生在「会话 → 文件面」。
- **`prefers-reduced-motion: reduce`**：取消位移，改为 ≤120ms 淡入淡出。
- **不要**为过渡引入路由库或整页共享元素动画。不要把终端滚屏、审批键显隐、会话切换面板做成页面过渡。
- v1 可以不做从左缘滑回；但一旦做，必须走同一套返回动画，不能只改手势不改运动。

画板 `P0` 可点对照。`K1` / `K2` 是规则卡，不用手机画框，也不和说明卡重叠。

## 6 密度、色、文案

- **密度**：桌面 28px 规范不适用于本壳主路径。不要把 `@pier/ui` 默认 `Button` 直接当手机主按钮。
- **色**：只走产品语义令牌（`background` / `card` / `action-accent` / `status-*` / `interactive-active`）。实现里删除 `bg-neutral-*`、`bg-emerald-*`、`text-red-400` 色阶。
- **等待项**：状态在预览窗口栏以小型标签表达，页首可汇总需要处理的数量；不重复整块黄色边框和摘要。工具品牌色仅用于真实品牌图标，状态色仍走产品语义令牌。
- **通知**：显示事件自身的标题、详情、发生时间与未读状态，保持消息产生时的信息，不用当前终端内容替换。无前置状态图标；会话通知进入对应会话，主机消息保留可读信息。存在未读时显示顶栏「全部已读」，操作后保留页面并即时更新。
- **主机**：设备行整行进入，连接态点画在设备图标右下。离线不降整行透明度，点按给去电脑上开的提示；移除放在该提示里，不要顶栏「编辑」。添加入口只留顶栏扫码。
- **实现词**：界面不展示 snapshot revision、交互 id。等待键上不要再写「按键会发到这台电脑的终端」。

## 7 导航

一条栈，没有全局底部导航：

```text
主机（根面）
  ├─ 添加主机 / 配对
  └─ 这台电脑（工作台，标题=电脑名，返回=主机，右侧=铃铛）
        ├─ 会话 → 变更 / 文件（会话内底部面板切同机其它会话，不推入）
        ├─ 变更 · git 根（可选快捷入口）
        └─ 通知（铃铛）→ 该会话
```

- 换机：从工作台返回主机列表，再点另一台。不要用底栏切换假装「还在同一层」。
- 系统叫醒点开：直接落到该会话；返回沿栈回去（会话 → 工作台 → 主机）。
- 连接态跟在电脑身份旁，不是正文调试行。

## 8 实现边界

- 不改帧协议、配对、会合、推送。
- 不在本轮做 T2 真终端、不引入路由库、不上 RN。
- 画板用 `pier/canvas` 积木在桌面里预览；量产控件活在 `apps/mobile-web`，不要从画板 import 进 SPA。
- 落地 PR 建议顺序：① 触控积木 + 令牌 + 安全区；② 主机→工作台层级栈 + 铃铛；③ 按画板实现七面；④ 推入/返回过渡。

## 10 本轮设计依据与验证范围（2026-09-05）

用户已确认：先完成工作台、会话阅读、等待回应、会话切换四个状态；随后按用户给出的 Moshi 终端列表截图改为预览网格，并核实输入能力。画板第一排按工作台、等待回应、原始按键、切换会话排列，P0 保留完整可点闭环；S1b 另列运行中，S1d 展示断线，S1u 展示等待但无法远程回应。

- [Moshi 主题](https://getmoshi.app/docs/personalization)：借鉴应用、阅读面、浮层的连续关系。Pier 仍沿用宿主令牌，产品状态色不随终端主题重派生。
- [Moshi 输入](https://getmoshi.app/docs/keyboard)与[会话切换](https://getmoshi.app/docs/jump-to)：高频操作在底部；临时选择按需展开。Pier 不复制未知键序列、原生触觉或完整快捷键配置器。
- [智能体概览](https://getmoshi.app/docs/agents-usages)：借鉴状态与信息层级，不照搬任务看板。其圆环为上下文余量，禁止拿来装饰任务进度。
- [Chat View](https://getmoshi.app/docs/chat-view)已有独立的数据来源与操作映射；不据此给 Pier 的 T1 纯文本屏幕添加聊天或语义审批接口。
- 不再把「不允许分组」「文件必须像 ls」「双击是唯一字号入口」当作固定规范。设计选择以真实内容和完整操作状态验证。

候选几何：导航区 60px、导航标题 17px、会话集合标题 20px、会话名 16px、说明 12–13px；终端 12 / 13 / 14px，默认 13px。主路径命中至少 44px，发送键高 48px；内容左右 16px；两列预览间隔 12px、预览 14px 圆角、回应区 20px 圆角、切换面板顶部 24px 圆角。以上为 Pier 当前 Canvas 的候选值，不是从 Moshi 截图反推的尺寸。

验证：393 × 852 主尺寸，补 360px / 320px 窄屏与亮暗主题；检查长路径、中文与英文混排、滚动、面板焦点与 Escape、发送防重复、通知已读和返回。浏览器里的模拟内容不能代替真实手机键盘、网络或 T2 终端验证。本轮更新画板与规范，量产 SPA 仍需后续按稿落地。

### 2026-09-05 输入与预览能力复核

- [`approval-bar.tsx`](../../../apps/mobile-web/src/components/approval-bar.tsx) 已有 13 键输入，数字默认折叠；不是解析后的终端选项。
- [`agent-attention-respond.ts`](../../../src/main/app-core/commands/agent-attention-respond.ts) 校验未决交互及 waiting 后发送单字节，返回 `accepted`。该结果不证明 CLI 选择成功，更不证明命令或回合完成；现有单测覆盖字节映射和门控，不能替代各 CLI 真机验证。
- [`terminal/screen.ts`](../../../src/shared/contracts/terminal/screen.ts) 只提供 `text / rows / cols / capturedAt` 等有界视口字段，无原生截图、ANSI 样式、选项数组或最后活动时间。预览以文本为基础，不能把采集时间写成活动时间。量产实现须限制可见预览的刷新数量并复用缓存，避免每张缩略图独立高频轮询。
- 本画板删除发送后定时生成终端结果、修改状态、自动制造完成通知的演示。P0 保留按键投递反馈与独立通知查看；下一次终端响应必须来自宿主事实。

### 2026-09-05 细节精修与验收方法

设计方向为移动端开发工具：以终端预览定位会话，以工具品牌识别身份，回应区与阅读工具明确分层。窗口边缘、显示区、页面底面使用不同的现有语义表面，避免所有内容落在同一块黑底上。编译和交互通过仅说明原型可运行，视觉质量需要单独检查。

本轮加载 [Emil Kowalski 的 emil-design-eng](https://github.com/emilkowalski/skills/tree/main/skills/emil-design-eng)，结合现有 Product Design audit 和 frontend-design。Skill 提供检查方法；实际取舍仍以 Pier 的能力边界与用户参考图为准，不把装饰动效机械套在高频操作上。

| Before | After | Why |
|---|---|---|
| 预览只有一个圆角文本块 | 窗口栏、内侧显示区、外缘分别处理；文本保留原始行形，优先露出末尾 | 让预览具有终端窗口的结构，仍不伪造 ANSI 或原生截图 |
| 三类会话都用通用终端符号 | 会话名下方使用宿主已有的 Claude / OpenAI 品牌路径，普通终端保留终端图标 | 工具身份可以直接识别；Canvas 不跨越宿主组件 import 边界 |
| 工具身份与状态挤在同一行 | 状态放在窗口栏；名称与工具身份各占一行 | 在窄屏保持稳定的文字层级与完整状态 |
| 回应按钮与字号、切换平级 | 独立回应区，主按钮打开按键；阅读工具位于下方 | 让等待状态有明确下一步，不伪装成自由文本输入框 |
| 数字键与功能键缺少完整的键盘布局 | 48px 键帽、二级数字区、统一背景层级、独立收起入口 | 维持 13 个原始按键的边界，发送中单独标明当前键 |
| 会话切换采用另一套标记 | 共享预览、品牌标识和状态标签；当前项用勾选与轻量边界表达 | 主页面和切换面板保持同一套识别方式 |
| 每处按压反馈独立定义 | 复用 150ms 按压反馈；键盘焦点及减少动态效果下取消缩放 | 提供触控反馈，同时保持高频键盘操作直接 |

可借鉴的公开做法及其在 Pier 的应用：

1. [Linear 的 UI 重设计复盘](https://linear.app/now/how-we-redesigned-the-linear-ui)：先形成代表设计方向的视图，再把完整流程与不同状态放进原型，检查环境、外观和层级。Pier 以工作台与会话页作为样板，先对齐，再扩展到其它画板；不通过反复换风格追求精致。
2. [Apple HIG — Layout](https://developer.apple.com/design/human-interface-guidelines/layout)：通过位置、对齐、留白与渐进披露组织信息，并在多尺寸、文字大小和语言条件下检查。Pier 检查实际手机宽度、长路径、中英混排和不同状态，不只看缩小后的整张画板。
3. [Emil Kowalski — Great Animations](https://emilkowal.ski/ui/great-animations)：动效需要明确目的，并兼顾频率、可打断性、性能和减少动态效果偏好。Pier 当前只精修即时按压反馈，不增加终端输出动画或发送后的庆祝效果。

视觉验收与功能验收分开：在 393px 查看层级和节奏，在 320px / 360px 检查折行、控件尺寸与底部提示，再核对亮暗主题、发送中、失败与失效。按压反馈不改变布局或挤动相邻项，状态反馈不推动工具条。真实手机触感、浏览器安全区与真实 CLI 回应仍需要量产阶段验证。T1 缺少 ANSI 与原生图像，不能用手写着色假装已具备这些数据；这个边界不妨碍做好窗口层次、工具身份与操作入口。
