# 侧栏与工作树整体切换：调研及待审方案

日期：2026-09-09。状态：**待用户审查，未实施**。

依据：[工作树区域设计](2026-09-07-workbench-worktree-tiles-design.md)，特别是 §4、§5.2–5.3、§9.4、§12；[现有实施方案](../plans/2026-09-08-workbench-worktree-tiles-implementation.md)。本提案补充本次侧栏交付的范围与切换契约，不替代已确认规格。

用户目标：侧栏按工作树整体切换；优先快速找到需要处理的会话。先调研与方案审查，再实施。

## 1. 推荐结论

**工作树行是整套工作内容的切换入口。每个工作树保留自己的终端、文件、审查、标签、分栏和活动视图；切回来继续原来的工作。**

采用同窗切换，沿用原规格「项目 → 工作树 → 会话」对象层级。工作树整体切换的生产契约仍以 [09-07](2026-09-07-workbench-worktree-tiles-design.md) §5.2 / §5.3 为准（任务在项目树之下；铃铛、更新留在标题栏）。本次侧栏画板的信息顺序是另一份覆盖：[侧栏设计契约](../../../.pier/canvases/workbench-sidebar-review/DESIGN.md)（任务在上、设置 / 通知 / 更新在侧栏底部）。画板不回写 09-07，也不改消息中心、操作反馈金标准。此次新增的核心行为是主窗口的工作树整体切换，以及保证它正确的最小底座。

例：A 左侧运行 Codex，右侧打开未保存文件；B 左侧运行开发服务，右侧查看差异。点击 B 后主区完整显示 B，A 的会话继续运行、文件草稿保留。点击 A 后恢复原标签、分栏比例及活动视图。

这只是同一次应用运行期间的切换保证。退出、崩溃、重启后的进程存活仍由现有终端机制定义，本次不扩大承诺。

## 2. 业界证据与可借鉴边界

本轮核对官方文档与 Pier 当前源码；没有执行竞品实机任务，也没有做用户可用性实验。下表区分明确文档事实与本提案的设计判断。

| 产品 | 官方可证实的行为 | 对 Pier 的判断 |
| --- | --- | --- |
| Orca | 每个工作树拥有自己的标签布局；切换工作树替换完整 pane tree，终端、浏览器、差异视图恢复原位置；分栏边界按工作树保存。[布局文档](https://www.onorca.dev/docs/model/tabs-panes-splits) | 与本需求直接对应，作为切换语义的主要参考。 |
| Orca | 侧栏默认按项目组织工作树；未读工作树以加粗表示；新建可在后台进行并显示进度与重试。[工作树文档](https://www.onorca.dev/docs/model/worktrees) | 借鉴对象层级、独立未读表达和对象内反馈。筛选菜单、议题绑定、归档生命周期等不照搬到 Pier。 |
| cmux | 侧栏条目代表 workspace，workspace 内含一组 panes，每个 pane 再含 terminal/browser surfaces。[概念文档](https://cmux.com/docs/concepts) | 支持「左侧切容器，顶部切容器内部视图」的层级。workspace 不必等于 GIT 工作树，Pier 的目录归属仍须自己严格定义。 |
| Zed | 同一窗口可切多个项目；文件树、GIT 状态与搜索范围分属项目，标签和分栏按项目保留。[项目文档](https://zed.dev/docs/windows-and-projects) 另提供将当前 workspace 切至已有 worktree 的入口。[GIT 文档](https://zed.dev/docs/git#git-worktrees) | 说明同窗切换应连带切换工具范围；文档未逐项保证每工作树终端进程与草稿的存活，不把它写成已验证事实。 |
| Cursor | Agents Window 可为智能体创建隔离 checkout，工作树承载该智能体的文件、依赖与改动。[工作树文档](https://cursor.com/docs/configuration/worktrees) | 这是智能体运行隔离的证据，不能直接推导出任意终端、编辑器及分栏都按工作树完整保留。 |
| VS Code Agents Window（Preview） | 活动会话决定 Files、Changes、Terminal / Tasks 等工具范围；其单面板实验布局按会话记住编辑器与宽度。[官方文档](https://code.visualstudio.com/docs/agents/run/agents-window) | 可借鉴工具范围随选择同步，但其所有权是会话；Pier 同工作树的多个会话共享区域，不能照搬成每会话一个工作台。 |

Orca 还明确把进程存活归给后台 PTY daemon，宿主重启或 daemon 故障会结束进程。[恢复文档](https://www.onorca.dev/docs/model/session-restore) 因此「恢复布局」和「进程继续运行」要分开验收，不能用前者证明后者。

## 3. 三种实现选择

| 选择 | 用户结果 | 代价与结论 |
| --- | --- | --- |
| **A：每工作树一套保留的工作区，切换可见性（推荐）** | 同窗整体切换；已打开视图、草稿和后台终端留在原工作树 | 需要把当前单工作区协调器改成窗口级协调器；已打开工作树占用内存。与规格及用户目标一致。 |
| B：每次把同一个工作区清空，再从保存布局重建 | 视觉上也能换一批标签 | JSON 只表达布局，无法独自保证未保存文件、终端实例和视图瞬态保留；容易把切换变成关闭再打开。不选。 |
| C：一个工作树一个窗口 | 工作内容隔离清楚 | 频繁切换变成窗口管理；与主窗口侧栏直接切换的目标不符。新窗口保留为现有次级动作。 |

这里的 A 是逻辑上的「一工作树一套内容」。已知但从未打开的工作树只保留索引数据，第一次进入才创建空区域；不能因为列出了 30 个工作树就启动 30 组终端。

## 4. 用户交互契约

| 用户动作 / 情形 | 结果 |
| --- | --- |
| 点击项目名称或折叠箭头 | 只展开 / 收起项目内容；当前工作树不变。 |
| 点击工作树 B | 主窗完整切到 B，恢复本窗 B 的布局和活动标签；A 保持后台运行。 |
| 再次点击当前工作树 | 保持原状，不重复创建区域、不重置滚动与焦点记忆。 |
| 点击 B 下的本窗会话 | 先显示 B 的完整区域，再激活该会话所在分栏与标签并交付输入焦点。 |
| 点击标有其他窗口名的会话 | 定位到拥有该会话的窗口；不复制会话、不把它搬回主窗。 |
| B 只在其他窗口有会话，点击的是工作树行 | 仍切主窗到 B 的本窗区域；本窗无内容则显示空区域，不抢其他窗口。 |
| B 从未在本窗打开 | 显示 B 的空区域；由用户显式新建终端或智能体，不自动启动进程。 |
| A 有未保存文件或终端输入，切到 B | 保留 A 的实例和草稿；切换本身不执行保存、丢弃或关闭。 |
| 点击项目 B 的「新建工作树」加号 | 以 B 为明确目标打开既有表单；不先切走当前工作区，取消保持原位置。 |
| 点击「任务」 | 在当前可见工作树的区域打开或复用既有任务面板；侧栏仍只有一条入口。 |
| A 的智能体在后台转为需要处理 | A 及其项目的聚合状态更新；不抢焦点、不改变侧栏顺序。 |
| 切到有未读会话的工作树 | 不一键清空整棵树的未读；只对用户实际进入的活动会话执行下述拟定阅读规则。 |
| 快速依次点击 A、B、C | 最后一次明确意图 C 生效；B 的迟到结果不能抢回选中、正文、焦点或状态栏。 |
| 目标读取失败或目录消失 | 保留已打开内容和可返回路径，原位显示原因及恢复动作；不静默丢弃草稿或停止会话。 |

**切换时同步变化的内容：**选中工作树、标签与分栏、区域身份及状态栏、活动面板、后续新建 / 打开动作的目标。窗口名继续遵守锚区域规则，不跟每次切换重命名。

**读取中的一致性：**立即显示目标身份与该目标的加载表面，旧工作树内容退出可见和可输入状态；绝不出现「B 的名称下面仍是 A 的内容」。GIT 摘要未读到时留空，不把旧值挪给新工作树。

## 5. 侧栏视觉与人体工程学

这是侧栏操作面，沿用 Pier 已有字体、语义颜色、Button / Item / Tooltip 等原语。生产侧栏位置仍以 09-07 §5.2 / §5.3 为准。下面是本次画板覆盖，权威文字在 [DESIGN.md](../../../.pier/canvases/workbench-sidebar-review/DESIGN.md)，不增加新的导航层，也不改写 09-07。

- 侧栏通高。顶部唯一「任务」入口；中部项目树独立滚动；底部固定设置、通知、条件更新。标题栏不重复这三项。
- 项目行只有箭头、名称、按需聚合状态、hover / focus-within 加号。「打开项目…」在项目标题旁，不占侧栏最底一行。
- 工作树行使用身份色块和叶子名；主 checkout 标「主目录」；右侧为变化摘要与一个状态点。选中底色表示主窗当前区域。只有工作树行有 HoverCard（路径、分支、有则展示 GIT；行上不画分支）。项目行、会话行、任务行没有悬停提示。
- 短 Tooltip 只给没有可见文字的纯图标；展开侧栏里提示朝上（顶栏收起按钮朝下），不朝工作区右侧展开。
- 会话行进一步缩进，智能体品牌图标与普通终端图标正确分开；名称沿用 tab short，不能擅自换成推测的任务标题。跨窗行可见文字用「其他窗口」，完整窗口名只进控件名称。
- 需要处理用 warning，运行中用 info；空闲会话无点。完成未查看只加粗，不能与当前选中的样式混淆。
- 项目折叠后仍保留聚合状态，便于发现需要处理的会话；自动状态变化不重排项目或工作树。
- 窄侧栏优先保住对象名称与状态点；窗口名允许受限截断。不得让长窗口名吃掉整个会话标题。
- 「本机目录」是分组标题；欢迎 ~ 不出现；最近项目只存在于空态。分支、同步数、议题和第二套工具栏不加入侧栏。
- 所有可点单行保持 28px；聚合状态和身份色块不单独占据 Tab 停靠点。颜色之外提供可读状态名称。

**本提案新增、待审后写入规格的细节：**

1. 侧栏内方向键只移动焦点，Enter 才执行工作树切换或会话定位，防止浏览列表时连续切换工作内容。项目展开和工作树激活是不同动作。W3C Tree View 明确区分焦点与选中，允许手动激活；这是本次取舍，而非该规范要求所有树必须如此。[W3C Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)
2. 工作树行保留键盘浏览焦点；恢复的是正文活动视图，进入正文才交付输入焦点。会话行的明确动作是定位，所以直接聚焦目标会话。终端聚焦期间不劫持方向键或既有快捷键。
3. 正式视觉实现先沿用现有 Sidebar 默认宽度 16rem；在窄宽度、长路径和四语样本下验证，再提交有证据的几何调整。规格没有定下的新增徽标、入口或工作树折叠控件，本次不先实现。
4. 完成未读的消除条件补为：用户明确进入该会话、目标窗口在前台、面板已显示并激活后，将本次进入时已经存在的相关消息逐条交给 NCS 标已读。包括点击工作树后恢复并呈现的活动会话；仅恢复布局中的后台标签不算查看。不清除未呈现会话或之后新到达的消息。消息已读不等于智能体的等待已解决。当前代码提供消息标已读 API，但尚未具备这条侧栏阅读桥接，实施时须补齐并测试。

## 6. 数据正确性要求

| 数据 | 唯一依据及防错要求 |
| --- | --- |
| 项目归组 | `worktree.list` 返回的主仓库路径 `mainPath`。`PanelContext.projectRootPath` 当前可能是 linked checkout 路径，不能据此把同仓库工作树拆成多个项目。 |
| 工作树身份 | 使用稳定 `worktreeKey` 与已有路径归属；同名目录和不同分支不能拿显示名当主键。切换不会执行 `git checkout`。 |
| 会话全集 | 窗口面板清单提供终端存在性，活动数据提供状态；Index 只含智能体，不能单独用它枚举会话。按窗口和面板身份合并，普通终端与项目命令不得漏掉。 |
| 会话名称与图标 | 名称走 tab short / `resolveAgentListTitle`；品牌只读 agentId。标题不是身份。 |
| 窗口名 | 读取 `WindowInfo.title` 的既有映射，兼容 Electron 与窗口分配 ID；本窗不重复标名。 |
| 变化摘要 | 读现有 GIT 摘要，正确保留行数 / 文件数回退；未知值不显示成 0。产品摘要经插件贡献或显示插槽提供，宿主不跨边界 import 内置 GIT 插件。 |
| 聚合与未读 | 工作树事实层统一计算三态聚合；侧栏只消费。完成未读由消息来源提供独立标记，不能由 idle 推断。 |
| 身份色 | 消费现有 `--identity-1…6`，按工作树身份持有；跨窗相同工作树不能漂色。 |
| 最近与插件 | 最近沿用现有 panel-context-state；任务入口经正式贡献声明。当前没有 `sidebarEntries`，不能硬编码一条入口假装贡献点已接通。 |

## 7. Pier 必须改到哪里

以下是最小可靠实现建议，尚未写入产品代码。

1. **窗口内协调多个工作树区域。** 当前 `AppShell` 只挂一棵 `WorkspaceHost`，`useWorkspaceStore.api` 只有一个。增加按工作树索引的区域容器及当前活动指针；只有被访问的区域挂载，切走后保留。宿主全局命令、插件关闭 / 更新桥接只注册一次，不能每个区域各注册一份。
2. **统一原生终端呈现。** 当前 `host-terminal-presentation.ts` 从一个 api 的 panels 构造整窗快照。改为一个窗口级写入方：终端存活集合包含全部已挂载区域，可见集合只含当前显示区域，活动终端只来自当前焦点。隐藏区域不能发出清空全窗的 reconcile。main 已有部分 managed-process 防误删保护，但不应把正确性寄托于兜底。
3. **布局按窗口与工作树持有。** 在现有 window-record 的 layout 内升级结构，保存各工作树布局及当前选中；不新增持久化文件。同运行期切换不经 `fromJSON` 拆毁 / 重建，JSON 用于启动恢复。旧混合布局做确定性归组，保留面板 ID 与所有内容。
4. **打开动作带明确工作树目标。** 文件、审查、终端及任务的打开路径路由至其所属区域。异步动作捕获目标，不能完成时随手读「当前 api」；否则用户切到 B 后，A 的迟到操作会开进 B。终端的区域归属在创建或首次可靠解析时确定；之后的 live cwd / PanelContext 变化不自动搬动终端。原规格 §7.3 的退化区域重绑另按既定分期实施，不能用每次 cwd 更新重新分组来代替。
5. **保留文件草稿与视图偏好。** 原编辑器实例和既有文档资源继续拥有草稿、撤销与阅读位置，区域布局不复制文档数据。只改变可见性，避免卸载触发清理；需要暂停的渲染工作与文档数据生存期分开。
6. **区分工作树导航与会话定位。** 工作树行固定作用于主窗；会话行以现有窗口 / 面板身份定位，先恢复所属区域再激活面板。保留当前跨窗机制，测试失效目标反馈。
7. **补足最少的界面衔接。** 主窗身份判断、侧栏开关、区域底部状态栏及同源事实必须随区域正确切换。沿用现有控件与位置规范，不展开新的主区设计。
8. **全窗快照与关闭语义一并改正。** `panel.list / focus / close` 和面板 ID 去重覆盖全部已挂载区域；隐藏区域事件不能覆盖当前活动面板。关闭当前工作树最后一个标签不等于整窗空，关窗检查、草稿保护和布局 flush 必须包含隐藏区域。
9. **兼容既有布局消费者与跨窗落点。** 现有窗口关闭、传输与恢复代码仍会读取旧布局的顶层 panels。新布局通过共享遍历器同时支持旧 / 新结构，避免被误判为空窗。既有跨窗标签移动进入主窗时，必须按面板所属工作树选目标区域；已有隐藏区域则恢复并复用，没有则先创建对应区域再接收，不得插入当前碰巧可见的另一棵树，不得产生相同工作树的第二个区域。无法确认合法落点时拒绝并保留来源。本次保留现有移动入口与双通道 claim，仅补工作树归属约束；区域墙、区域拖拽和弹簧预告仍按后续分期。

## 8. 审查后的验收案例

| 场景 | 必须观察到的结果 |
| --- | --- |
| A 的终端持续输出，切 B 再切 A | 进程身份不变、输出继续，无重新启动。 |
| A 编辑文件但不保存，B 查看同名文件 | 两个路径的内容不混淆，A 草稿及撤销历史仍在。 |
| A 左右分栏，B 上下分栏，往返切换 | 各自比例、标签、活动面板恢复；无重复标签。 |
| A→B→C 快速切换，B 较慢 | C 保持最终可见，B 的结果不抢回界面。 |
| A 的异步打开文件期间切到 B | 文件仍归 A，不在 B 新增标签。 |
| A 的终端执行 cd 进入 B | 普通已归属终端仍在 A 区域和 A 的会话列表中；点击会话回到 A，实时 cwd 不驱动迁移。 |
| 点击无本窗会话的工作树 | 本窗空区域，不跳窗、不自动开进程。 |
| 点击跨窗会话 | 到达原窗口与原会话，没有复制或迁移。 |
| 项目收起后其会话需要处理 | 项目状态仍可见，展开能找到会话，位置不漂移。 |
| 切到含多个未读会话的工作树 | 未实际查看的会话继续保留未读。 |
| 创建表单取消 / 工作树加载失败 | 原工作未丢失，有明确反馈和恢复路径。 |
| B 关闭最后一个标签，A 在后台运行 | A 的终端与草稿仍存活，不把整个窗口关闭。 |
| 升级旧混合布局 / 执行现有标签跨窗操作 | 面板不丢失，新布局不被旧读取者误判为空；所有面板 ID 在窗口内唯一。子窗 B 标签移回正在显示 A 的主窗时，只落到复用或新建的 B 区域，失败保留来源。 |
| 重启恢复布局 / 关闭应用 | 与现有恢复和关闭保护一致，不把隐藏区域当已关闭。 |
| 亮暗、长名称、四语、窄侧栏、键盘 | 28px 密度、清楚焦点、状态可读、无截断覆盖，附实际渲染截图。 |

验收方法：关键状态与路由用单元 / 组件测试；进程身份、草稿、原生可见性与整窗切换用真实 Electron 场景验证。视觉判断只在渲染后作出，本提案不宣称已达到最佳视觉或已通过无障碍验收。
