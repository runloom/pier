# 工作台体验与人体工程学

日期：2026-09-03；重设计与文档收敛：2026-09-05

状态：信息架构提案，待实施与用户验证。本文集中说明分析、字符设计稿、交互和迁移约束；图中的目录、智能体和议题均为示例，不表示产品已实现。

中心思想：**核心高度内聚，大部分能力通过插件扩展，共同服务一条稳定的工作主线。**

用户应形成的预期：**选好目录，在终端里工作；按需添加工具，仍在熟悉的工作台中继续。**

## 1. 为什么上一版仍有心智负担

上一版补齐了目录、焦点和通知的正确性，但仍以功能清单组织产品：给每项能力找入口，再用分组和说明补救。用户仍要先理解实现分类，才能决定去哪里。这次先确定用户对象、动作与后果，再安排能力的位置。

| 问题 | 已核对的现状 | 对用户的影响 |
|---|---|---|
| 「任务」有三种含义 | 宿主运行构建 / 测试；议题插件跟踪需求；工作树表单用「开始任务」表示启动智能体 | 误以为命令通过、智能体结束、议题完成是一回事 |
| 插件分类外露 | 议题在新建菜单，记忆在项目设置，分屏在插件设置 | 相近意图要先学插件名才能找入口 |
| 核心与扩展没有共同原则 | 已有插件所有权，但上一版仍逐项安排功能，未规定扩展后哪些体验必须稳定 | 用户把每项能力当成新的子产品，担心必须全部配置 |
| 新建菜单目的混杂 | 启动、浏览文件、查看议题、创建目录、开窗口混在一起 | 菜单难以预测，插件越多越拥挤 |
| 状态缺少对象 | 命令、智能体、议题都显示进行 / 成功 / 完成 | 看到了状态，却不知道谁完成了什么 |
| 作用范围不清 | 当前目录、共享项目记忆、外部议题来源并不一一对应 | 误以为新工作树隔离全部数据，或换目录会切换所有工具 |
| 启动带隐式指派 | 议题启动调用会写负责人，自动提示词包含认领要求 | 用户想启动本机执行，却同时改变外部责任归属 |

当前界面抽样中，`build:native` 运行控制与「任务跟踪」标签可同时出现，窗口也可包含多个目录。代码与抽样支持这些冲突确实存在，但不能代替完整可用性测试；具体依据列在 §11。

## 2. 中心思想与取舍

以 pi 的小核心、可扩展理念为参照。其官方文档明确将终端编码核心与 extensions、skills 等扩展方式分开；据此映射到 Pier：核心负责让工作台中的运行、定位与交互可靠一致，领域知识和工作流由插件拥有。Pi 是智能体运行工具，Pier 是多工具工作台；借鉴职责划分，具体能力边界按 Pier 的宿主身份判断，依据见 §11.2。

**小核心与开箱可用同时成立。** 默认体验随附文件、GIT 等常用插件，普通终端可直接使用；已有可用 CLI 时可直接启动智能体。随产品附带属于交付选择，领域逻辑仍归插件。议题、记忆、分工等按需使用，首次打开无需先挑选、安装和配置一套插件组合。

**找到工作目录 → 在终端里做事 → 查看文件和更改 → 继续。** 智能体是终端里的一种工作方式，构建 / 测试是项目命令，议题和记忆是按需使用的工具。

```text
工作目录  --->  终端：命令 / 智能体  --->  文件与更改
                       ^                       |
                       +------ 继续工作 <------+

实现职责（不作为界面菜单层级）
  工作台核心：目录定位 / 终端与面板 / 焦点 / 状态观察 / 交互规则
       |
       +-- 通过既有贡献接口接入领域插件
             +-- 文件 / GIT：默认体验随附
             +-- 议题 / 项目记忆：需要时使用
             +-- 协作与连接：原生分屏适配、SSH、账号等
```

| 路线 | 得失 | 决策 |
|---|---|---|
| 保持功能菜单，只统一名称 | 改动小，但开始、浏览、配置仍混杂，扩展后再次拥挤 | 不足以解决本次问题 |
| 用任务中心统管全部能力 | 必须新增共同任务身份、生命周期与同步，要求用户登记工作 | 与 Pier 定位冲突，不采用 |
| 以目录与终端为主线，由插件按目的扩展 | 核心保持内聚；插件须遵守共同入口、范围和交互约定 | 采用 |

「中心」落实为稳定操作逻辑。默认仍是一条可输入的普通终端；无需经过首页、任务登记、议题授权或记忆配置。不新增工作台任务实体、自动调度器、常驻智能体侧栏或第二套聊天产品。

插件与宿主遵守同一套可用性要求，主次由用途和频率决定，不能按 builtin / external 区分。扩展后，目录的含义、开始的方式、状态的主语和返回的位置保持稳定。每项新能力都须说明：帮助完成什么 → 操作什么对象 → 数据归谁 → 从哪里进入 → 完成后回到哪里。

## 3. 对象、数据与作用范围

| 用户对象 | 含义与所有权 | 不能混同为 |
|---|---|---|
| 当前目录 | 这次在哪份文件中工作；普通目录也合法 | 窗口内所有工具的统一项目 |
| 终端 | PTY 与既有面板，命令 / 智能体执行和继续输入的地方 | 议题卡或宿主会话台账 |
| 项目命令的一次运行 | 现有 TaskRun，保留退出结果、输出及依赖步骤 | 需求生命周期 |
| 文件 / 更改 | 磁盘与该工作树的 git 状态 | 自动归属于某个智能体的成果 |
| 议题 | GitHub / Linear / Jira 的工作项；来源拥有状态与负责人 | 本机执行进度 |
| 项目记忆 | 记忆插件拥有的本机项目知识 | 聊天同步或每个面板独立的记忆库 |

一个议题可以关联多个终端和多次运行，一个终端也可以处理没有议题的工作。只有插件已明确记录关联时才显示链接，不按时间、标题相似或当前目录猜测。

| 范围 | 例子 | 界面交代什么 |
|---|---|---|
| 当前工作目录 / 工作树 | `/work/pier-login` | 启动位置、文件与更改来源 |
| 同一项目 | 主目录与 linked worktree | 项目记忆等共享范围；非 git 按既有项目身份解析 |
| 外部来源 | `GitHub · acme/pier` | 议题真正来自哪里，本地路径不能替代来源名 |

选择目录只打开 / 聚焦那里的普通终端。已经打开的文件、更改和议题面板保留自己的来源；改来源须在工具内显式操作。窗口继续容纳多个目录，系统窗口名也不充当项目身份。

## 4. 消除「任务」与「分配」的混义

### 4.1 统一名称，保留兼容

| 旧用法 | 新主标签 | 明确含义 |
|---|---|---|
| 运行任务… | 运行项目命令… | 构建、测试、开发服务等命令 |
| 任务运行控制 / 任务输出 | 命令运行 / 命令输出 | 一次命令运行的控制与结果 |
| 任务跟踪 / 任务管理 | 议题；插件设置中称「议题跟踪」 | 外部工作项 |
| 立即开始任务 | 创建后启动智能体 | 创建目录后启动，不创建议题或计时 |
| 开始工作 | 交给智能体… | 从议题进入一次明确的本机启动 |
| 分配 | 设置负责人… / 交给智能体… | 外部责任人与本机执行分别操作 |
| 任务完成通知 | 命令运行结束 / 智能体已完成回复 / 议题状态已更新 | 说明发生变化的对象 |

四语同时覆盖入口、空态、运行控制、失败、通知及快捷键说明。英文对应 `Run Project Command…`、`Command Output`、`Issues`、`Start Agent…`。保留 `pier.run.task`、`pier.tasks`、`task.*`、TaskRun、tasks.json、panel kind、原快捷键及用户自定义 label；不因产品更名重建数据或面板类型。

搜索保留「任务 / 运行任务 / 任务跟踪」旧别名，但结果显示明确对象。「任务」仍可用于用户标题、第三方字段、原生 CLI 与文件格式名，不能作为三类对象共同的宿主主标签。

### 4.2 三种分工行为

1. **设置负责人**：修改外部 assignee，不启动本机进程。
2. **交给智能体**：在确认的目录启动，不默认改负责人、关闭议题或宣称完成。
3. **智能体自行分工 / 分屏**：沿用原生能力，`pier.agent-splits` 适配到 Pier 面板；宿主不另造成员管理、自动派工或统一 one-shot API。

「开始全部可做议题」留在议题工具的高级动作中。主动执行前展示数量、各项目录、资源成本与失败结果，使用有限批次；查看看板、打开目录或启用插件不触发派工。

### 4.3 三份状态各有主语

| 显示 | 能证明什么 | 不能推导 |
|---|---|---|
| `test · 通过` | 这次命令按成功条件退出 | 智能体完成、议题可关闭 |
| `智能体 · 等待输入` | 智能体在等用户 | 代码已验收、议题完成 |
| `GitHub · 处理中` | 来源系统的议题状态 | 本机有智能体运行、测试通过 |

议题主状态来自外部来源，本机执行是副信息。没有真实工作流状态、只能按指派分列时，列名用「未指派 / 已指派 / 已关闭」，不能伪装为「待办 / 进行中 / 完成」。命令步骤依赖与议题依赖分开，不合成全局任务数或进度条。

## 5. 主界面与稳定入口

### 5.1 主工作台与位置

```text
+----------------------------------------------------------------------+
|  [/work/pier v]                          [工具] [智能体 2] [消息]    |
+----------------------------------------------------------------------+
|  [登录超时] [+]                                                      |
+----------------------------------------------------------------------+
|  Codex · /work/pier                                                  |
|  > 修复登录超时，并补充回归测试。                                    |
|                                                                      |
|  已调整重试逻辑，测试通过。请检查更改。                              |
|                                                                      |
|  [输入下一步…                                               ]        |
+----------------------------------------------------------------------+
|  智能体 · 等待输入                              [更改 2] [文件]      |
+----------------------------------------------------------------------+
```

| 入口 | 只回答什么 | 呈现 |
|---|---|---|
| 位置 | 我在哪；如何打开另一个目录 | 活动路径可点击，完整路径可复制 |
| ＋开始 | 在这里启动什么 | 默认智能体、其他智能体、新工作树启动、终端、项目命令 |
| 工具 | 要查看什么或调整哪项项目能力 | 一个有文字的工具按钮 |
| 智能体 | 谁在工作、谁等我、回哪个终端 | 既有计数与全量找回列表 |

消息与设置沿用现有入口。对应插件可用时保留文件 / 更改的就地按钮，并与工具菜单调用同一动作。标题栏不叠加议题数、命令数和智能体数，也不新增项目侧栏、插件图标排或工作台总览。

点击位置：当前完整目录 → 最近项目 → 打开项目文件夹。最近项显示必要父目录以区分同名，过长路径保留可辨认尾部与完整可访问名称。File、`⌘O` 和最近项进入同一打开动作；无路径时显示「选择工作目录」，普通 shell 仍可使用家目录。

### 5.2 开始与工具菜单

字符稿展示文件、GIT、议题和记忆已启用，且 Codex 可用的场景，不表示首次安装全部展开。核心规定入口的目的和排序规则，领域条目由实际可用的贡献填充。

```text
+------------------------------------+  +------------------------------------+
|  ＋开始                            |  |  工具                              |
|  工作目录 /work/pier               |  |  当前目录 /work/pier               |
+------------------------------------+  +------------------------------------+
|  智能体                            |  |  文件与更改                        |
|    启动 Codex       默认 · ⌘⇧A     |  |    文件                            |
|    其他智能体…                     |  |    更改                            |
|    在新工作树中启动智能体…         |  |    新建工作树…                     |
|                                    |  |  项目                              |
|  终端与命令                        |  |    议题                            |
|    新建终端                        |  |    项目记忆                        |
|    运行项目命令…                   |  |    项目设置…                       |
+------------------------------------+  +------------------------------------+
                                        |    添加与管理工具…                 |
                                        +------------------------------------+
```

默认配置的开始菜单收敛为图中五类动作；它们规定操作范围，不把五个业务实现写死在核心。新增插件的查看与设置入口归工具，领域内的创建和批量操作留在工具内。默认智能体显示真实名称，其他提供方在同一菜单第二层完整列出，保留返回及底部「管理智能体…」。没有可用 CLI 时，用一条「安装或启用智能体…」替代提供方启动项；检测中与未安装要区分。

普通新终端遵守自己的目录偏好；若实际目标不同于菜单目录，须在该行说明。智能体、项目命令和文件动作不受该偏好改写。新工作树入口要求 git；不满足时说明原因。

开始菜单只搜索开始类动作。打开文件夹归位置入口，新建文件归文件工具，裸新建工作树归工具，新建窗口归 File；删除 Welcome 创建项。命令面板仍可搜索全量动作，不能照搬精简集合。

### 5.3 工具扩展规则

工具菜单打开时固定来源面板与目录。SSH 插件启用后可增加「SSH 主机…」，打开既有选择器，新终端显示远程身份。各表面未安装或已停用插件的业务入口不占空位；已启用但缺目录 / 授权的工具保留发现入口，可导航到配置，但业务执行仍受 §9.2 的资格检查约束。「添加与管理工具…」始终通向现有官方插件管理页，不自动安装、授权或连接。

首层只贡献适合独立发现的对象入口：议题 CRUD 在议题内，记忆开关在项目设置内，账号切换在账号设置内。分组至少两项才显示标题；位置固定、无 MRU，全部入口可滚动 / 搜索。搜索旧「任务」时明确区分项目命令和议题，跨入口结果也必须显示真实动作。

安装、启用、停用、卸载按既有插件生命周期执行，界面如实区分已生效与需重启。操作前交代受影响的面板、执行和数据；停用 / 卸载不顺带清空项目知识或改变外部议题。仍在使用的能力须明确如何结束或恢复；未成功完成不得把入口移除当作成功。普通终端与其他工具继续使用，不承诺插件崩溃隔离或原生进程一定可接回。

### 5.4 找回与返回

```text
+----------------------------------------------------------+
|  本机智能体                                      共 12 个|
|  [搜索智能体、目录或窗口…                           ]    |
+----------------------------------------------------------+
|  登录超时                  Codex · 需要你处理            |
|  /work/pier                本窗口 · 终端 1               |
|  ...                                                     |
|  终端 12                   Codex · 运行中                |
|  /work/notes               开发窗口 · 终端 12            |
+----------------------------------------------------------+
|  上下键选择 · Enter 定位 · Esc 返回                      |
+----------------------------------------------------------+
```

图中省略中间行仅为排版。实际列表搜索前不得截断 8 项；可限制可见高度，不能丢候选。空态区分检测中、安装 / 启用、选择目录、在已知目录启动；搜索无结果允许清除查询。定位已有智能体不产生新实例。

tab 与列表使用同源主标题，保留原生标题 / 用户钉名；副信息展示提供方、状态、目录、窗口与稳定定位号。更新保持选中身份和滚动；目标消失时取消选择，Enter 不能改投相邻项。聚焦成功才关层并交出键盘，失败保留重试。

项目命令仍用既有控制条、运行选择器与输出视图找回，不混入智能体列表。通知写明事件对象与来源；有更改的智能体回合结束优先「查看更改」，回到来源工作树；具体结果、已读及跨窗处理见 §9.5。

### 5.5 通过使用建立理解

用户先学会共同操作，再在需要时了解扩展。启用议题后，工具中出现「议题」，选择后仍在同一工作台打开面板，交给智能体后仍回到终端；用户通过这次操作学会新增工具的使用方式。主工作区保持目录、终端和正在看的内容，技术上的核心 / 插件分类只在管理与诊断时解释。

| 时机 | 界面表达与用户应学会的事 |
|---|---|
| 第一次进入 | 普通终端直接可用，位置、开始、工具、智能体入口说明各自用途；没有插件配置必修步骤 |
| 想增加能力 | 「添加与管理工具…」进入既有插件管理；简述「按需添加工具，继续在当前工作台使用」，说明用途、入口、作用范围及配置要求 |
| 使用或配置工具 | 仍按共同菜单、面板、弹窗和返回规则操作；管理详情可查由哪个插件提供，日常按钮不逐个挂插件徽标 |
| 停用或移除 | 明确入口何时消失、现有面板如何处理、数据是否保留；「清空数据」始终是另一个明确动作 |

## 6. 插件展开后的完整流程

### 6.1 宿主与插件分工

| 归属 | 职责 | 用户得到的稳定预期 |
|---|---|---|
| 工作台核心 | 终端与面板运行、目录定位、布局与焦点、智能体及命令运行观察、通知投递、插件运行与共同交互约定 | 工具之间切换和返回可靠，状态有来源 |
| 默认随附的领域插件 | 文件、GIT 等日常工具的业务界面与操作 | 开箱能完成基本工作，不必先拼装产品 |
| 按需使用的领域插件 | 议题来源 / 状态 / 负责人、记忆、原生分屏适配、SSH、账号等 | 需要哪项就使用哪项，数据和业务决策归相应工具 |
| 原生智能体 / CLI | 自身执行、分工、原生扩展与任务策略 | 原有命令和习惯继续成立，Pier 不另造执行协议 |

「默认随附」与「按需使用」可重叠，不决定 builtin / external，也不承诺每个内置组件都可卸载。既有 TaskRun 保留命令执行、输出、取消与恢复职责，不承接议题生命周期；本提案不要求先搬迁其模块才能改善体验。

新增能力依次判断：原生工具已有的动作直接走原生入口；需要融入 Pier 的领域展示与交互由插件衔接；只有依赖宿主身份、且需共同遵守的运行与交互机制才进入核心。文件与 GIT 的高频使用不构成把业务移回宿主的理由。

扩展能力由既有 command / action、panel、projectSettings、数据投影和受约束的宿主 facade 共同提供。插件可组合展示、动作与设置；数据和规则各有唯一所有者，共享目录与动作结果用于衔接。自己的面板 / 设置复用同一业务组件，跨插件通过既有公开契约协作，不互相 import renderer，不把数据再汇成全局工作台任务。

本轮入口改造只给现有 action `surfaces` 增加 `tools-menu`，复用 registry、CommandsView、搜索和 dispatcher，builtin / external 同构。宿主按贡献表面取动作，不按插件 id 硬编码业务名单；贡献注销同步清理入口与订阅，不新增能力中心、插件任务 DTO 或通用编排服务。

扩展范围继续遵守当前治理：只接入内置与官方受管理插件。此理念不自动引入第三方市场、任意来源加载或进程隔离承诺；现有插件声明与 capability 校验是工程纪律边界。Pier 插件与智能体自身的 extensions / skills 分属两个扩展层，管理界面应说明安装到哪里、影响哪个工具，不能暗示安装一处会自动给所有智能体生效。

### 6.2 议题、状态与交给智能体

```text
+----------------------------------+  +------------------------------------+
|  终端 · /work/pier               |  |  议题 · GitHub / acme/pier         |
+----------------------------------+  |  本地目录 /work/pier               |
|  命令 test · 通过 [输出]         |  +------------------------------------+
|                                  |  |  #142 修复登录超时                 |
|  Codex                           |  |  GitHub · 处理中                   |
|  已完成修改，等待你检查。        |  |                                    |
|                                  |  |  负责人 Alice [设置负责人…]        |
|  [输入下一步…                  ] |  |  本机智能体 Codex · 等待输入       |
+----------------------------------+  |                                    |
|  智能体 · 等待输入               |  |  [回到终端]                        |
+----------------------------------+  +------------------------------------+
```

议题持续显示外部来源，本地执行目录另列。列表 / 看板复用既有 panel、数据和 applet，DAG 留作专项能力，首开不要求理解 Canvas。切换工作目录不切换这个议题面板；来源与本地仓库不对应时，启动前要求明确执行目录。离线标数据时间，权限不足可读时只限制写动作。

没有活关联时显示「交给智能体…」；已有可用终端时优先「回到终端」，另开一次须显式选择。启动前的确认如下：

```text
+------------------------------------------------------------+
|  交给智能体                                          [X]   |
|  #142 修复登录超时 · GitHub / acme/pier                    |
|  原目录 /work/pier · 负责人 Alice                          |
+------------------------------------------------------------+
|  智能体                                                    |
|  [ Codex v                                            ]    |
|  分支名称                                                  |
|  [ fix/login-timeout                                  ]    |
|  新目录 /work/pier-fix-login-timeout                       |
|  创建基线                                                  |
|  [ 当前工作树的当前提交 v                             ]    |
|                                                            |
|  当前未提交更改不会自动带入；同仓库记忆仍共享。            |
|  环境文件按配置复制；负责人保持 Alice。                    |
+------------------------------------------------------------+
|                                      [取消]  [创建并启动]  |
+------------------------------------------------------------+
```

提交固定创建并启动，不再添加「是否启动」勾选；只创建目录从工具里的通用工作树表单进入。新路径随分支和目录规则更新，基线默认取发起工作树的当前提交，不能偷偷换主目录 HEAD。议题标题 / 链接直接作为启动说明，不要求用户重填同一段需求。

取消不产生目录、进程或外部变更。成功后焦点进入新终端，议题留下返回链接。创建只隔离文件；同仓库记忆和 git 引用仍可共享，环境文件依配置复制，端口与服务不保证隔离。

| 结果 | 用户看到的处理 |
|---|---|
| 创建前失败 | 说明原因，不显示虚构目录 |
| 目录已创建，准备 / 启动失败 | 保留路径，说明已完成部分，允许打开终端后重试 |
| 终端已启动，关联保存失败 | 保留终端与文件，重试保存关联，不重复启动 |
| 独立的负责人写入失败 | 只报告外部写失败，不回滚已经运行的终端 |

### 6.3 项目记忆

```text
+------------------------------------------------------------+
|  项目设置 · pier · 本机                               [X]  |
|  [项目记忆]                                                |
+------------------------------------------------------------+
|  主目录 /work/pier                                         |
|  本次从 /work/pier-login 打开                              |
|                                                            |
|  供本机项目的智能体读取约定，同仓库工作树共用。            |
|  不会自动同步终端对话。                                    |
|                                                            |
|  [x] 启用项目记忆                                          |
```

从「工具 → 项目记忆」直接进入现有设置的明确项目 tab。真实产品按 git common dir / 既有项目身份解析；非 git 无法确定时选择项目，不按活动窗口名或面板 id 猜测。图中「已接入」必须来自真实检测，启用不等于每个 CLI 已读取全部条目。

即时修改无保存 footer，关窗用 X；启停影响新启动的智能体，不中止已有引擎。条目、删除、清空、打开文件继续在原设置页，删除 / 清空 / 关闭各自说明后果并采用相应确认。没有条目或未启用不影响终端、命令和议题使用。

### 6.4 原生协作与配置

原生智能体分屏接入普通 dockview 面板与智能体列表。没有协议证据时不显示「分配完成 / 已同步记忆」。账号与 CLI 安装保留在既有设置，不将登录、选项目、开记忆、连议题组合成每次必过的向导。

## 7. 六条工作路径

| 目的 | 路径 | 无须先理解 |
|---|---|---|
| 随手改代码 | 位置选目录 → ＋启动智能体 → 输入 | 议题、记忆、任务登记 |
| 运行构建 / 测试 | ＋ → 运行项目命令 → 看输出 | 议题进度、智能体分配 |
| 围绕需求动手 | 工具 → 议题 → 交给智能体 → 新终端 | 命令运行模型、插件 API |
| 并行另一项修改 | ＋ → 新工作树启动 → 新终端 | 外部议题创建 |
| 复用项目约定 | 工具 → 项目记忆 → 核对范围与条目 | 每个工作树另配记忆、聊天同步 |
| 找到谁需要处理 | 智能体入口 → 定位终端 → 继续 | 插件来源、议题是否关闭 |

原生 CLI 直接使用始终成立。辅助工具用完回到执行终端，不要求用户进入另一套工作生命周期。

## 8. 人体工程学与验证

### 8.1 界面纪律

- 共享单行控件默认 28px，内容行最小 28px，多行自然增高；既有紧凑面板例外继续保留。
- 高频动作可见，快捷键加速；提供方最多展开一层，保留返回与 Esc，不用隐藏入口换表面简洁。
- 打开菜单 / 选择器固定目标，键盘进入当前浮层；取消回原终端，成功交给目标，不误投旁边终端。
- 键盘焦点使用产品 focus-visible 指示，保持合理 Tab 序；状态用文字与形状辨认，颜色和动画只辅助。
- 窄窗优先保留位置、工具、找回；完整路径和名称仍可访问，默认终端不添加永久引导或插件推荐区。
- 所有动作有可辨认结果。强自然反馈不叠 toast；短失败用短提示，技术详情走宿主 alert，后台事件归 NCS。

### 8.2 先验证理解，再比较速度

首轮 6–8 名目标用户，至少各 3 名熟练 CLI 与首次使用 Pier 的图形工具用户。逐人记录，不预先教菜单位置或快捷键，不用小样本宣称统计意义上的最优。

| 实验 | 初始验收目标 |
|---|---|
| 看主界面 15 秒后解释如何开始 | 能说清目录、启动、文件 / 更改；不认为必须建任务或开记忆 |
| 同时看到命令通过、智能体等输入、议题处理中 | 分别解释三个状态，无人据命令成功认定议题已完成 |
| 预测设置负责人 / 交给智能体的结果 | 不期待前者启动进程，或后者自动改负责人 |
| A 工作树开记忆，B 工作树改文件 | 理解文件分开、同项目知识共享，不用窗口名代替范围 |
| 未安装专业工具时完成修改，再添加议题工具 | 主循环无需额外配置；新增能力能被发现，位置 / 开始 / 返回规则保持一致 |
| 未讲解架构，让用户说明如何扩展 | 知道可以添加工具，能预测入口和影响范围；不要求说出「核心 / 插件」术语 |
| 停用议题或记忆，再继续终端工作 | 能区分工具停用与数据删除，不认为关闭工具就关闭了议题或结束全部运行 |
| 无快捷键提示找到议题、记忆、多行输入 | 各入口无帮助发现率初始目标 ≥80%；失败先改命名 / 位置 |
| 从 12 个智能体定位指定目标 | 全量可达、同名可分辨、状态刷新不换目标 |
| 启动失败、关闭来源窗、切换目录 | 知道哪里成功、如何继续；不误投、删目录或审查错仓库 |

再对比当前版本的点击、指针距离、按键负担与完成时间。首次启动中位数 30 秒、熟悉后定位等待智能体 5 秒是初始产品预算，需实测修订，不是行业定律。错目录执行、错误归属、误删目录及状态错误联动为发布阻断项。

字符稿只用于评审结构和交互，不证明可访问性或心智负担已解决。功能、人体工程学和用户理解分别验收；测试结果进入实施记录后才更新方案状态。

`tools-menu` 透传 builtin / external 类型、schema、facade 与注销行为。动作保留 `ActionInvocation` 来源，不复制 handler；搜索复用 `rankSearchDocuments` / `rankActionsForPalette`。项目设置深链补显式项目路径和 contribution id，扩展已有 `app.openSettings`，沿用 `projectsFocusPath` / `projectsTab`，不建第二个 store。

### 9.2 目录、最近与资格

默认 / 新窗口 / 布局重置 / 插件清空补位复用普通终端布局，不创建 Welcome；关闭最后一个面板后关窗并应用现有保护。打开目录按以下顺序：

1. 捕获来源 windowId、分组与面板；可选 `path` 由最近项直接传入，否则 `environments.pickProjectDirectory()`。取消不登记、不启动。
2. 校验 realpath、权限，拒绝 Pier 自身受管理主目录；普通 shell 家目录合法。
3. main 注入来源窗，经 `panel.open { paths: [{ path }] }` 共用 `ensureDirectoryTerminal`。只复用同窗同 cwd 普通终端，排除智能体、已结束智能体及命令终端，不向程序注入 `cd`。
4. 成功直接使用返回的 panelId / context 续跑，不等待描述水合；来源窗 / 指定分组消失则失败，不偷偷换窗。
5. 成功打开即异步 `localEnvironments.recordOpen(path)`。主 checkout 更新 projects，linked worktree 只更新其 worktreeBindings.lastOpenedAt；登记不阻塞后续启动。
6. 登记失败不回滚、不重复打开；请求完成后一次 alert 说明未更新最近，不等智能体回合结束。最近取 8 条仅是导航快捷集合，失效路径可重选、不回落家目录。`ENVIRONMENTS_CHANGED` 更新 File，`MENU_COMMAND_REQUEST` 保留参数，不 seed `.pier/environment.json`。

目标优先级：显式路径 / 选择结果 / 通知来源 → invocation.sourcePanelContext → 触发时 active panel 快照 → 动作前提。菜单打开、命令面板进入或快捷键触发时捕获，后续焦点变化不能改写。

智能体使用目标 cwd；项目命令 / 文件树使用该目标 projectRootPath，非 git 回落 cwd。`terminalNewCwdPolicy` 仅控制普通终端；正常路径与缺目录续跑均不得无条件复用其 `captureAnchoredTerminalTarget`。

`project-path-action-gate.ts` / dispatcher 增加 `fallback?: "open-project-folder"`，只补可补齐的前提。智能体 / 项目命令 / 文件动作的鼠标、快捷键、Enter、Index 共用续跑；应用未 ready、CLI 检测中 / 不可用、插件 / 权限缺失仍是真禁用，不调用 handler。

审查 / 提交 / 工作树必须满足 git 前提；记忆单独解析项目身份。目录选择返回 `{ sourcePanelId, sourcePanelGroupId, sourcePanelContext }` 后重查资格，最多续跑一次；失败不循环选目录，同一未决启动抑制重复提交。

### 9.3 智能体与命令状态

全量 Index 移除 `AgentIndexCountsControl` 的 `limit: 8` 及搜索前 slice。tab / Quick Pick 使用 `resolveAgentListTitle`。稳定定位号在面板描述登记时分配，窗口内生命周期不复用、不随排序改变；跨窗读来源值，不建历史台账，跨宿主恢复不承诺永久序号。

保留 `⌘⇧Y` 零选择跳转、状态形状及减少动画，无目标给短反馈。命令保持 TaskRunsSnapshot、committed output binding、background / terminal 区分、运行最近、取消与恢复协议；只读 committed run。命令成功不反写 ForegroundActivity 或关闭议题，议题选择不冒充输出 run 选择。

### 9.4 工作树与议题交接

通用工作树表单归 GIT 插件，议题交接表单归议题插件；共用宿主 content dialog / Field 与 worktrees facade，不跨插件 import renderer 表单，也不新增表单路由服务。垂直字段、28px 主控件、宿主 sticky footer「取消 | 创建 / 创建并启动」，不能在 body 仿 footer。

通用表单手动 / AI 命名 × 启动开 / 关四组合均合法，移除 `mode === "ai" && startTask` 耦合。明确的「新工作树启动」预填 startTask=true 与默认 agentId；手动不强迫提示词，AI 需说明，命名服务失败不阻挡手动创建。

稳定工作流习惯只在用户显式切换时经该表面模块即时记住；入口预填不回写偏好，取消也不清已有习惯。草稿路径、分支、说明和此次智能体不粘滞；情境字段按本次快照推导，具名偏好归设置，禁止通用弹窗记忆层。

议题提交前固定 provider / repo / itemKey / URL / 执行目录 / 智能体，先查已有活关联。移出 `task.startWork` 中隐式 `setAssignees`，移除自动提示词 `Claim this task`；用户另行明确要求认领不在此限。内部 `work.claim` 仅是多窗单执行门，保留但不能当负责人更新反馈。

多次执行关联继续归插件 overlay。`orchestrate.ts` 后续失败删除目录的 catch 必须改为 §6.2 的部分成功处理，不能删除已创建目录、用户已有目录或已启动终端。

### 9.5 通知归属与完成反馈

智能体状态即时更新，git 探测不阻塞。agent-attention 捕获 agentRef / cwd / gitRoot / windowId，经 main git 边界最多等 1s，向 NCS ingest 一次；超时是未知，不为补结果重复 ingest、计数或响铃。

| 探测结果 | 有序动作 | toast | 消息中心 |
|---|---|---|---|
| 来源工作树有更改 | open-review → focus-panel | 首个可用「查看更改」，最多一个操作 | 最多两个可用操作 |
| 无更改 / 非 git / 未确认 | focus-panel | 回到终端 | 回到终端 |

通知只说明工作树更改，不声称全由该智能体 / 本回合产生。`git.openReviewPanel { cwd: capturedGitRoot, windowId }` 优先来源窗；来源窗失效则在点击窗打开同一目录。面板失效隐藏回终端，目录有效仍可审查；点击重查路径、git 与插件，更改已提交显示来源空态，不另找仓库。

dispatcher 返回真实完成结果，成功后已读 / 关 Popover；失败反馈并保留重试。NCS 保持唯一系统消息写入和投递判定，保留 key-window 路由、去重、OS 白名单、DND 与声音，不新增 renderer 打断通道。

### 9.6 焦点、输入与关闭

工具 / 开始 Popover 复用终端 Web overlay 纪律：注册全屏覆盖、钉 Web 键盘但不吞全局快捷键、Dialog 打开时让路，仅终端 outside-dismiss 分支补终端焦点。菜单到 Dialog 使用宿主解锁机制，不加业务 setTimeout。

增强输入默认关闭，仅合资格智能体使用；保留右键、命令面板、`⌘⇧I`。`⌘⇧A` 唯一用于默认启动，附件改走按钮及无冲突入口。打开进编辑器，取消回原终端，发送遵守原焦点策略，不向普通 shell 抢输入。

| 操作 | 后果与恢复边界 |
|---|---|
| 切 tab / 最小化 | 不主动停止程序，不承诺休眠期间执行 |
| 关闭终端 | 结束本地执行，应用现有 close guard 与结果态 |
| 关闭窗口 / 退出 | 不承诺继续运行，有条件时可原生恢复 |
| 常规界面刷新 | 验证保留活 PTY，与 renderer 崩溃恢复分开记录 |
| 重启 / 更新后接回 | 有原生恢复信息才继续，缺失则说明，不用冷启动冒充恢复 |

保留既有终端结果态和原生恢复机制，不新增外部 daemon、公共 transcript API 或第二套会话历史。

### 9.7 检查范围
