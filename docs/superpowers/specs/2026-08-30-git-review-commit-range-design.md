# Git 审查：提交连续范围

日期：2026-08-30  
状态：现行（提交选择器连续范围净变化）  
权威边界：不改 [2026-07-31 Git Review 金标准](./2026-07-31-git-review-gold-standard-endstate-design.md) 的正文、加载、骨架。本文只扩展「提交」目标怎么选。

## 一句话

Changes 顶栏「提交」选择器：勾一个提交立刻单选；再勾另一个以**上一击为原点**扩成连续净变化。第一段仍是「未提交 / 提交 / 分支」。

## 产品

- 只有左侧 28px 勾选列可点；点标题、作者、时间不选、也不关窗。
- 勾一个提交：立刻审这一份，勾上，它成为原点。窗保持开着。
- 正文无行背景。勾选列：选择态勾选框 > 悬停勾选框 > 范围中间小圆 > 普通勾选框。线从框心接到下一格，两端不超出。
- 已选范围用实线；悬停/键盘预览用灰色线叠在已选之上，同段圆点和空心勾选框也跟灰色，不改勾选。
- 已有原点时悬停另一勾选框（或键盘移到那一行）：勾选列从原点画出预览线。
- 再勾一个提交：立刻审 `原点^..该提交`，该提交成为新原点（A–B 后再勾 C → B–C）。
- 自动选中的最新提交在未勾选前不是原点，也不勾上。
- 点外面、Esc 或切走面板时关掉，保留当前审查目标。焦点回到触发器。
- 触发器：人读标题可截断；一段时计数（或尚不知 N 时的 `from–to`）单独一块、次要色、永不截断。标题用最新提交（审查头）。短 hash 只作无标题时的兜底。定位符留给 tab。`+/-` 是净变化，不进触发器。
- 左侧 `@pier/ui/checkbox`。不要第四个 scope。不要行上「到最新」。
- 无祖先关系：拒绝。不要把多个 `git show` 拼起来。
- 相对默认分支仍走「分支」。命令面板选提交仍单选。

## 契约

`commit` 目标可选 `fromOid`（最老、含）：

- `{ kind: "commit", oid }`：相对 `oid^1`（根提交相对空树）
- `{ kind: "commit", oid, fromOid }`：`fromOid^1..oid`

`fromOid` 缺省或等于 `oid` 则归一成单个提交。main 用 `merge-base --is-ancestor` 核对两端；反了就换；两边都不是祖先则 `invalidSource`。

面板身份：`commit:<oid>` 或 `commit:<fromOid>..<oid>`。评论 scope 跟审查目标走；可处理评论仍仅未提交。

## 不做

第四个 scope、任意勾选并集、两个 from/to 选择器、Cursor 常驻提交栏、会话 lastTurn 快照、命令面板多选、审查加载/CodeView 改动。
