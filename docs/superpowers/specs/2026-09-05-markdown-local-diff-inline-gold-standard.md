# Markdown 局部差异内联展开：金标准方案

状态：待评审的设计提案，尚未实施。2026-09-05。

更新：同日用户选择优先实施渲染后的文档差异，见 [现行规格](2026-09-05-files-local-diff-peek-design.md) 与 [实施计划](../plans/2026-09-05-markdown-rendered-diff.md)。本文的“仅源码、不增加视图切换”限制已被取代；内联容器、关闭策略与滚动锚点仍是独立提案，不能视为当前产品行为。

适用范围：Files 的 Markdown 阅读模式。现行实现与已完成验证仍以 [Files 局部修改预览规格](2026-09-05-files-local-diff-peek-design.md) 为准。本方案获采纳后，替代其中 Markdown Popover 的呈现和关闭策略；源码编辑模式沿用现有 CodeMirror 内联预览。

## 目标与取舍

用户点击文档左侧色条，能在原位置看清准确的修改，继续阅读相邻正文。验收围绕四件事：正文可见、版心一致、阅读位置稳定、修改完整。

行业提供不同选择：

- [VS Code](https://code.visualstudio.com/docs/sourcecontrol/staging-commits#editor-gutter-indicators) 在源码色条处提供内联差异预览。
- [JetBrains](https://www.jetbrains.com/help/idea/editor-gutter.html) 提供局部浮层与变更操作；浮层能避免正文重排，但会遮挡附近内容。
- [GitHub](https://docs.github.com/en/repositories/working-with-files/using-files/working-with-non-code-files#rendering-differences-in-prose-documents) 为文档提供源码和渲染后的差异视图。

这些资料没有规定 Markdown 阅读界面必须使用哪一种容器。本方案选择内联，是针对 Pier 阅读、局部检查、继续阅读这一流程的产品判断。代价是后文会随展开下移，必须处理滚动锚定。

## 默认呈现

1. 收起时保留左侧色条；hover 只强化命中反馈并显示延迟提示，不自动打开差异。
2. 单击后，在对应文档块后的正常排版流中插入一个差异区。顺序为：原文块、差异区、下一原文块。差异区不覆盖正文、不进入右侧大纲区域。
3. 一个 Files 面板最多展开一处。点击同一变更再次收起；点击另一处时移动同一展开状态并展示对应完整差异。
4. 活动色条保留原有变更颜色，用已有加粗状态指示展开；不增加新的整段底色、指向箭头或连接线。
5. 展开状态只属于当前面板会话，不保存为阅读偏好。

## 几何与样式

| 项目 | 确定规则 |
| --- | --- |
| 左右边界 | 跟随当前文章版心盒，继承 `--md-measure`；舒适档根 `42rem`，宽屏 `100%`，窄面板自然收缩 |
| 色条、评论、大纲 | 继续消费既有布局常量与唯一布局壳；差异区不占用这些槽位 |
| 块后间隔 | 原文块到差异区净距 12px；差异区到后续正文使用既有段间距，不叠加两套外边距 |
| 外框 | 单层弱边框，复用源码 peek 的 `rounded-md` 和语义色；无浮层阴影、模糊、额外卡片壳 |
| 工具栏 | 单行；28px 图标按钮，上下各 4px 内边距；底部一条弱分隔线 |
| 正文高度 | 自然高度；内部正文最大 `min(320px, 正文滚动视口高度的 45%)`，同时保证工具栏与正文总高适配可用高度 |
| 滚动 | 只有差异渲染器持有内部滚动区；工具栏保持可见；内部滚到边界不带动外层文章 |
| 长行 | 保留完整文本并自动换行，正常支持范围内不产生预览页横向溢出 |
| 字体 | 差异使用宿主代码字体、代码字号和 1.75 倍行高；不叠乘 Markdown 正文字号缩放；应用整体缩放仍正常生效 |
| 明暗 | 差异主题跟随 Markdown 当前实际纸面明暗；背景不透明。宿主明暗与纸面明暗不一致时也必须可读 |
| 动效 | 展开、收起和键盘导航即时完成；不做高度、缩放或平滑滚动动画；hover 沿用轻量反馈 |

工具栏左侧为“源码差异”，比较说明“HEAD → 当前内容”为次级信息；存在未保存内容时显示“未保存”。右侧为位置与导航（仅多处变更）、完整审查、关闭。窄面板先隐藏次级比较说明，再截断标题，按钮与未保存标记保持可用；完整比较说明保留在可访问描述中，不挤出第二行。

## 展示什么

- 继续复用 `PierDiffExcerpt` 与原生差异组件，展示精确源码差异。完整连续变更及前后最多三行未改内容均保留，包含纯新增和纯删除。
- 保留真实两侧行号、加减号、行内变更高亮、选择和复制。语法配色沿用共享代码主题，不新增 Markdown 专属彩色方案。
- 比较语义始终为 HEAD 到当前文档，包含未保存内容。保存或暂存不改变比较基线。
- 完整审查保持显式次级入口。当前完整审查只包含已保存修改，未保存时需明确说明；只有未保存修改时提示先保存，不自动保存或假装精确定位。
- 此处原有的“仅源码、不增加视图切换”限制已失效。现行内容层复用 Markdown 渲染器与原生 jsdiff，并提供预览 / 源码切换；未新增另一套比较资源。若后续采纳内联容器，应直接复用该内容层。

## 块定位与合法排版

色条的点击锚点与差异范围分别保存：前者决定展开位置，后者决定显示哪些修改。

- 通过稳定变更 ID、当前文档版本和 Markdown 已有源码范围找到被点击的文档块；不从像素反推行号。
- 正常段落、标题、代码块，展开于所属顶层块后；嵌套引用、列表、表格使用其所属顶层可独立排版容器后的槽位。插槽与评论包裹后的整个块是兄弟，保持文章版心宽度，不把工具栏塞进表格行、列表标记或正文行内。
- 同一差异跨多个块时，只展开一次。位置跟随用户本次点击所属的块，正文仍展示整个连续变更，不能因某个块只覆盖部分行而裁掉差异。
- 巨大的表格、列表等容器可能使合法槽位离点击位置很远。此时执行一次明确的最小定位，让展开区工具栏和首行可见；记录此次导航前的位置。若打开后未发起文章滚动或新的导航，关闭时返回该位置；否则按当前阅读锚点规则关闭。不得为了保证“原地”而破坏 DOM 语义或遮挡正文。
- 纯删除定位到后继块之前；没有后继块则使用文末槽位。全文删除或没有任何可见文档块时使用文首槽位，由文档“查看修改”入口打开。
- 隐藏内容的变化优先使用源码顺序上最近后继块之前的边界；没有后继块则使用文末，全文无可见块则使用文首。仍展示准确源码，不伪造一个看似修改过的可见段落。
- 懒加载页先按源码范围定向加载目标页，再依靠真实块布局打开。展开本身不要求加载整篇文档。

## 阅读位置与滚动

滚动补偿与主动导航必须区分；不能只记下打开时的 `scrollTop` 并在关闭时无条件写回。

1. **当前块可见时打开**：记录点击所属正文块的稳定标识和屏幕偏移。插入并完成必要高度测量后，补偿布局变化，使该块保持原屏幕位置。
2. **靠近底边**：若差异区工具栏和首行不可见，只做使两者可见的最小滚动。长差异不要求整块同时进入视口。
3. **切换变更**：按下一处目标重新定位并展开；保留目标块位置。此操作允许合理导航，不归类为意外跳动。
4. **关闭**：优先保留关闭当下第一个可见的普通正文块及其屏幕偏移。若视口完全落在差异区内，使用所属正文块作为后备。用户已经滚动过时不恢复到最初打开的位置。
5. **异步尺寸变化**：复用现有阅读锚点能力，在本次布局事务内处理字体、图片、分页和差异实际高度变化。用户发起滚动或新的导航后，取消过时补偿，避免持续拉回。
6. **滚动范围限制**：浏览器在文首、文末可能限制补偿；按实际范围钳制，不用额外空白伪造位置不变。

同一滚动容器只允许一个锚定协调者负责补偿；避免浏览器自动锚定和多个手写补偿各执行一次。这里复用现有 `cross-mode-anchor` / 阅读记忆机制，不新建第二套滚动真源。

## 交互与生命周期

| 事件 | 行为 |
| --- | --- |
| hover 色条 | 提示可查看修改，不展开 |
| 点击同一色条 | 展开 / 收起 |
| 点击另一处、上一处 / 下一处 | 切换唯一展开区；首尾不循环 |
| 滚动文章、点击普通正文、选择或复制 | 保持展开，不因离开视口或点击外部自动收起 |
| 关闭按钮、Escape | 收起，按当前阅读位置补偿；只在键盘交互需要时归还焦点 |
| 文件 / 模式 / 面板切换、宿主对话框打开 | 清理展开状态，避免旧内容跨表面残留 |
| 文档内容或 HEAD 变化 | 旧差异失效即关闭，下一次打开使用新快照；不保留看似实时的旧内容 |
| 只改面板尺寸、代码字体、纸面明暗、舒适 / 宽屏 | 保持展开并重新布局，不重置差异选择或无故夺焦点 |
| 比较中、失败或超限 | 同一位置展示已有加载、失败或按需比较状态；失败可重试，不挂出另一种浮层 |

Markdown 需要移除现有 Popover 专属的“点击外部”和“锚点离开视口”关闭逻辑。源码编辑模式的既有关闭规则不随之改写。

## 键盘与可访问性

- 复用 Files 的命令入口和 Alt+F5 / Alt+Shift+F5。键盘打开后聚焦工具栏；鼠标打开保留当前文本选择。
- 展开区有“源码差异”可访问名称、比较范围描述，色条提供展开关系和状态。多处导航只播报位置，不把整个差异反复送入 live region。
- Tab 只经过真实可操作控件；差异每行和状态标签不进入 Tab 序。工具栏操作期间可通过 PageUp / PageDown 滚动差异正文，Escape 收起。
- 焦点样式复用产品 `focus-visible`；无全局焦点陷阱，菜单和对话框保持现有优先级。
- 加减号与行号提供颜色以外的差异信号。新增文案同步中英日韩；未保存比较范围同时对视觉和辅助技术用户明确。

## 实现边界

保留共享资源、基线接口、Worker、差异渲染器和单实例状态；改动集中在 Markdown 的插槽、锚点、呈现与生命周期。

- `git-changes/surface.tsx`：区分源码与 Markdown 展开容器策略，继续维护每面板唯一状态。
- Markdown IR 渲染与分页：增加窄的可选块边界插槽与目标页加载入口，继续复用原有文章和评论包装。
- `git-changes/markdown-reveal.ts`：将浮层跟随及离屏关闭职责替换为块定位与内联展开的阅读位置协调。
- `peek-content.tsx` 与 `PierDiffExcerpt`：复用工具栏、主题、字体、原生测高及内部滚动；只增加必要的呈现参数。
- 大纲 scroll-spy、搜索、评论命中和 Git 色条测量只识别真实文档块。差异插槽不注入文章源码属性或 heading，不能被识别为第二份正文。
- 打开插槽不重新解析全文，不重建其他块、表格、代码块或评论编辑状态。观察器读写合并，防止插槽测高触发循环。

实施时同步现行规格和治理测试，将本提案与旧 Popover 契约的冲突一次消除；遵守文件尺寸与目录密度边界。

以下是待实现后实测的验收要求，不代表当前代码已通过。

| 验收项 | 通过条件 |
| --- | --- |
| 截图中的普通引用场景 | 差异展开于引用块后，引用与后续标题均未被覆盖；文档左右版心一致 |

| 尺寸覆盖 | 实际预览面板宽 320 / 480 / 768 / 1280px，舒适 / 宽屏均无横向溢出、无大纲或评论槽位侵占 |
| 高度 | 短差异末行不裁切且无多余空洞；长差异首末行均可完整查看，内部滚动不带动外层 |
| 变更种类 | 单处、多处、纯新增、纯删除、文首 / 文末 / 全文删除、跨块、链接地址和格式修改均准确 |
| 复杂文档 | 嵌套引用 / 列表、宽表格、代码块、图片延迟加载、隐藏内容、懒分页保持合法结构与正确锚点 |
| 主题与字号 | 宿主和纸面明暗的交叉组合、代码字号变化、Markdown 阅读缩放、应用缩放均可读且布局稳定 |
| 交互 | 鼠标选择保留、键盘打开 / 导航 / 滚动 / 退出、多实例、版本失效、Dialog 让路均符合契约 |
| 现有能力 | 大纲只追踪文章标题；搜索不重复计数；评论位置和表格偏好不因展开丢失 |
| 性能 | 打开已有差异不重新比较、不解析全文；沿用同一测试环境和样本验证缓存打开 P95 ≤100ms |

验证顺序：块定位 / 滚动锚点的有意义单测，交互组件回归，真实 Electron 几何断言和完整面板截图，再执行相关静态与治理检查。源码既有场景需回归，确认共享组件调整没有带来退化。
