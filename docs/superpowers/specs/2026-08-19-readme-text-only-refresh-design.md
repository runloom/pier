# README 纯文字收口设计

## 背景

README 的多轮产品截图同时承载智能体状态、终端、Git 审查和 Canvas，缩放后信息密度过高，也让读者先判断演示数据与画面真实性，反而延迟理解 Pier 的产品定位。

## 决策

根 README 改为纯文字产品前门，不再使用截图、图注或演示数据说明。首屏按以下顺序组织：

1. 一句话定位：Pier 是本地 AI 开发工作台。
2. 为什么需要 Pier：原生 CLI 智能体持续运行后，用户需要统一查看状态、回到终端并审查变更。
3. 核心工作流：启动智能体 → 关注需要处理的会话 → 返回原生终端 → 审查 Git 变更。
4. 核心能力与产品边界。
5. 安装、CLI、深入文档、贡献与安全信息。

Canvas 保留为一项真实能力，与终端、会话状态、工作树、文件与变更、可保存布局并列，不再承担独立视觉展示。

## 范围

- 删除 `assets/readme/` 下本轮生成的三张截图。
- 删除 README 中全部图片引用、图注和演示数据披露。
- 撤回仅为截图修复会话标题的运行时代码、测试和变更日志条目。
- 保留本轮已经核实的文档索引、开发指南和 CLI 用户手册改进。

## 验收标准

- README 不含 Markdown/HTML 图片。
- 首屏无需图片即可说明 Pier 是什么、解决什么问题、用户如何完成核心工作流。
- Canvas 是能力项，不被描述为任务台账、看板或自动调度器。
- `assets/readme/` 不再存在。
- 本地相对链接、Markdown 格式和 CLI 手册治理测试通过。
- 独立审查确认文案与当前产品能力一致，没有遗留截图专用改动。
