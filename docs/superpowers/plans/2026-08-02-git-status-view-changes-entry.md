# Git 状态菜单补充查看变更入口

## 目标

当工作树没有未提交变更时，Git 状态菜单仍提供一个明确的“查看变更”入口，打开现有的变更差异面板。该入口不自动选择比较分支，也不改变工作树。

## 全局约束

- “无未提交变更”继续是灰色、不可点击的状态说明，不能改成动作。
- 仅在干净且没有暂停 Git 操作时，在菜单底部动作区显示“查看变更”；已有可点击“变更”或暂停操作行时不得重复显示。
- “查看变更”排在“切换分支”之前，复用既有 `viewChanges` 动作、图标、文案和 `openGitChangesPanel` 路径。
- 打开的差异面板初始范围保持“未提交”；用户可在既有范围选择器中选择提交或分支。
- 不新增 Git 主进程、预加载、共享契约或国际化接口，也不新增分支查询和默认比较基准。

## Task 1: 在干净状态提供查看变更入口

### 实现

1. 调整 Git 状态下拉模型：干净且没有未提交变更时，将 `viewChanges` 放在动作区首位；有未提交变更或暂停操作时保持现有动作区，避免与已有可点击行重复。
2. 复用下拉组件已有的 `viewChanges` 分发和状态项已有的 `openGitChangesPanel` 回调；不改动“无未提交变更”信息行。
3. 不修改已有中文“查看变更”文案或图标映射。

### 测试

1. 先写并运行失败测试，证明干净模型会提供 `viewChanges`，而有未提交变更或暂停操作时不会额外提供该任务。
2. 扩展下拉组件测试：干净菜单可见并可点击“查看变更”，点击时调用 `onViewChanges` 且菜单关闭；灰色状态行仍保持禁用。
3. 扩展状态项集成测试：干净状态从菜单点击“查看变更”会以当前组和默认“未提交”目标调用现有面板打开路径。
4. 运行相关 Vitest 测试、类型检查，并在可用的 Electron/Playwright 路径中验证干净临时仓库的菜单入口和面板打开流程。
