# 智能体状态真实轨迹验收设计

## 目标和完成标准

为 27 个主动状态集成建立可执行的跨层证据：每个非 `unsupported` 的
“智能体 × 状态维度”至少由一份独立列举的官方形状轨迹覆盖。当前共 148 项。
原先统计的 161 项错误地把 `advisory` / `none` 的 `Stop` 当作 `ready` 证据；这类
事件现在只记为运行时控制事实，不进入用户可见状态覆盖。
Aider、Kiro、Crush 不提供主动状态，必须有实际生产入口不可达或不产生状态输出的负例。

完成时必须同时证明：

- 原生载荷经过实际安装命令、受管插件或转录记录对账器。
- 每条输出都通过严格 v3 `agentHookEventSchema`。
- 事件进入真实 `ForegroundActivity` 聚合器。
- 快照断言来自 `snapshot()`；广播断言来自独立的 `onChange` 回调记录。
- `waiting`、终态和子智能体使用完整成对轨迹，不以单个事件冒充闭环。
- 轨迹声明的覆盖集合与证据矩阵的 148 项严格相等，并拒绝额外能力。

## 当前结构为什么不足

现有提供方测试已有约 20 段真实生产器到聚合器的链路，但分散在各测试文件中，没有
类型化的覆盖集合，也无法证明每个非不支持维度都经过了完整链路。部分提供方只验证配置、
生成源码或 schema，没有进入聚合器；报告中的覆盖数量无法从一个治理测试重新计算。

矩阵与 `runtime.emittedMappings` 的严格等集只能证明两个声明一致，不能证明官方载荷能让
实际生产器生成正确事件，更不能证明聚合和广播结果正确。

## 所有权划分

| 单元 | 负责 | 不负责 |
| --- | --- | --- |
| 类型化轨迹夹具 | 独立列举官方原生动作、载荷、预期检查点和来源说明 | 读取矩阵自动生成载荷；复制生产映射算法 |
| 传输驱动 | 执行实际安装命令、受管插件或转录记录对账器 | 判断 UI 状态语义 |
| 轨迹观察器 | 严格解析 v3、摄入聚合器、分别记录快照与广播 | 识别提供方原生字段 |
| 参数化治理测试 | 运行全部轨迹、验证检查点和 148 项严格等集 | 用字符串等集代替执行 |
| 证据矩阵 | 提供最终应覆盖维度集合 | 生成测试输入或预期事件序列 |

## 数据流

```text
官方原生动作
→ 实际钩子命令 / 托管插件 / 转录记录对账器
→ JSONL
→ agentHookEventSchema.parse（必须 v3）
→ ForegroundActivityAggregator.ingestAgentEvent
→ snapshot() 记录
→ onChange 广播记录
→ 类型化检查点
→ 148 项覆盖严格等集
```

快照和广播是两个独立证据：观察器在每次摄入后读取快照，同时从聚合器的 `onChange`
回调收集广播；测试不得把一次 `snapshot()` 读取同时命名为两层。

## 轨迹检查点

- `lifecycle`：`SessionStart` 建立 hook 活动但无状态；`SessionEnd` 清除对应活动。
- `ready`：可信 `Stop` 或规范终态使状态进入 `ready`。
- `processing`、`tool`、`waiting`、`error`：对应快照状态真实可见。
- `completed`、`interrupted`：输出分别含 `TurnCompleted`、`TurnInterrupted`，
  且聚合后为 `ready`。
- `subagent`：开始后计数为 1，停止后回到 0，主会话身份和状态不被覆盖。
- `waiting`：请求进入 `waiting`，结果事件按同一编号解除，随后回到 `tool` 或
  `processing`。

## 明确禁止

- 从证据矩阵或 `runtime.emittedMappings` 自动生成原生载荷。
- 直接构造规范事件绕过生产器。
- 只比较 `{nativeEvent, pierEvent}` 字符串。
- 用源码包含字符串、配置存在或最终单状态代替轨迹执行。
- 在共享观察器或聚合器中增加提供方分支。
- 对无法执行的传输降级为伪事件；必须列出精确缺口并停止该项验收。

## 最小实施与验证

测试侧新增类型、观察器、按传输分片的夹具和一个参数化治理测试。先写 27/148/3 的
严格等集测试并确认因夹具缺失失败，再按钩子命令、托管插件、转录记录对账器补齐。
复用现有真实运行辅助函数；需要抽取时只抽测试代码，不把轨迹夹具写进生产集成。

## 需求到证据

| 需求 | 证据 | 通过条件 |
| --- | --- | --- |
| 27 个主动集成 | 参数化治理测试 | 智能体集合与矩阵 `active` 集合严格相等 |
| 148 个非不支持维度 | 覆盖键集合 | `agentId:dimension` 严格等集，无缺失或额外项 |
| 官方形状生产器 | 独立轨迹夹具 + 传输驱动 | 不直接构造规范事件 |
| 严格 v3 | 观察器 | 每行都经过 schema 且 `v === 3` |
| 聚合快照 | 每步 `snapshot()` 检查点 | 状态、身份、计数符合轨迹 |
| 实际广播 | `onChange` 记录 | 至少一条广播包含对应状态变化 |
| 高风险闭环 | `waiting`、终态、子智能体检查点 | 请求结果、终态、开始停止成对 |
| 非主动负例 | Aider、Kiro、Crush 生产器测试 | 无状态 JSONL 输出 |
