闲置 Mac 全新系统 → Pier E2E runner
=====================================

我（主力机上的 agent）无法直接操作你尚未联网/未开 SSH 的笔记本。
请你在笔记本上完成「门闩」三步，其余可用脚本自动完成。

────────────────────────────────────
A. 只有你能做的门闩（约 15–30 分钟）
────────────────────────────────────

1) 完成 macOS 开机向导，登录到桌面（保持登录，不要停在登录窗口）。

2) 打开「终端」，安装 Xcode Command Line Tools，装完再继续：
     xcode-select --install

3) 安装 Homebrew（官方一行，按提示输入密码）：
     /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   Apple Silicon 装完后执行它提示的：
     echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
     eval "$(/opt/homebrew/bin/brew shellenv)"

4) （推荐，便于主力机远程接管）系统设置 → 通用 → 共享 → 打开「远程登录」
   允许「所有用户」或你的管理员账户。

5) 记下笔记本：
   - 局域网 IP：系统设置 → 网络，或终端 `ipconfig getifaddr en0`
   - 用户名：终端 `whoami`

6) 把主力机 SSH 公钥写进笔记本（在笔记本执行，把 KEY 换成主力机 `cat ~/.ssh/id_ed25519.pub`）：
     mkdir -p ~/.ssh && chmod 700 ~/.ssh
     echo 'KEY' >> ~/.ssh/authorized_keys
     chmod 600 ~/.ssh/authorized_keys

把「IP + 用户名」发回主力侧 agent，即可 SSH 继续；
或跳过远程，直接在本机跑 B 段。

────────────────────────────────────
A2. 主力机 SSH Host（必做，否则 test:e2e:auto 会静默回退本机）
────────────────────────────────────

在**主力开发机**编辑 `~/.ssh/config`，追加（IP/用户按实际改）：

  Host pier-e2e
    HostName 192.168.x.x
    User xyz
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
    ConnectTimeout 8

连通性检查（须 BatchMode 成功、无需密码）：

  ssh -o BatchMode=yes pier-e2e 'echo ok; hostname; whoami'

失败时：确认笔记本远程登录已开、authorized_keys 已写入、IP 未因 DHCP 变更。
IP 变了只改 HostName 一行。

默认 Host 名是 `pier-e2e`；可用环境变量覆盖：
  export PIER_E2E_SSH_HOST='xyz@192.168.x.x'

────────────────────────────────────
B. 一键环境（笔记本终端）
────────────────────────────────────

# 若还没有 SSH key 访问 GitHub，先：
#   gh auth login
# 或生成 ed25519 并加到 GitHub SSH keys

git clone git@github.com:runloom/pier.git ~/pier
cd ~/pier
# 若默认分支没有 scripts/e2e-runner，可临时 checkout 带脚本的分支
BOOTSTRAP_YES=1 bash scripts/e2e-runner/setup-mac.sh

# 首次 libghostty + native 可能 5–15 分钟；全程接电。

────────────────────────────────────
C. GitHub Actions self-hosted（可选，最省心）
────────────────────────────────────

# 笔记本已 gh auth login 且对 runloom/pier 有 admin：
cd ~/pier
bash scripts/e2e-runner/install-actions-runner.sh

# 或在主力机生成短时 token：
#   gh api -X POST repos/runloom/pier/actions/runners/registration-token --jq .token
# 再在笔记本：
#   RUNNER_TOKEN=... bash scripts/e2e-runner/install-actions-runner.sh

检查：https://github.com/runloom/pier/settings/actions/runners
应出现 Idle 的 pier-e2e-*

触发：
  gh workflow run e2e-self-hosted.yml -f suite=smoke
  gh workflow run e2e-self-hosted.yml -f suite=full

────────────────────────────────────
D. 主力机日常（不打扰当前电脑）
────────────────────────────────────

推荐（AI / 人类统一入口，优先闲置机，不可达再本机）：
  pnpm test:e2e:auto
  # 或
  bash scripts/e2e-runner/run-e2e.sh
  bash scripts/e2e-runner/run-e2e.sh tests/e2e/startup-stability.spec.ts

run-e2e.sh 远端会：
  - 把本机 git HEAD 同步到闲置机（git bundle，不必先 push）
  - checkout 同一 SHA 再跑 playwright
  - 本机有未提交改动时默认拒绝远端（请 --local），避免假绿

强制本机 / 强制远端：
  pnpm test:e2e:local
  pnpm test:e2e:remote

仅测已提交 HEAD 且工作区 dirty：
  bash scripts/e2e-runner/run-e2e.sh --allow-dirty-remote

手动 SSH：
  ssh pier-e2e 'cd ~/pier && git rev-parse --short HEAD'

或只推代码，用 Actions self-hosted 跑 full（需 workflow 已在远端仓库）。

────────────────────────────────────
E. 笔记本使用注意
────────────────────────────────────

- 测试时接电；setup 会尽量把「接电源时 sleep」关掉
- 保持用户已登录桌面（锁屏可以，注销不行）
- Electron e2e 会在笔记本上闪测试窗——不影响主力机
- 勿在 runner 上同时登个人敏感会话当主力机用
